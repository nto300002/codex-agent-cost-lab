# M2: 認証・顧客

## ISSUE-006: ローカル認証とDBセッションを実装する

- 種別: feature
- 依存: ISSUE-005
- 状態: 実装済み
- 目的: Seedユーザーで安全にログイン・ログアウトできるようにする。

### スコープ

- パスワード検証
- DBセッションとCookie
- ログイン、ログアウト、現在ユーザー取得
- 未認証時の401

### 受入条件

- 3ロールのSeedユーザーでログインできる。
- 認証失敗時にユーザーの存在を漏らさない。
- Cookieにパスワードや機密値を保存しない。
- ログアウト後のセッションを再利用できない。

### 検証

```bash
pnpm test:auth
```

## ISSUE-007: ロール別認可ポリシーを実装する

- 種別: feature
- 依存: ISSUE-006
- 目的: MEMBER、MANAGER、ADMINの認可を一箇所で判定する。

### スコープ

- Customer、Deal、Activity、User、AuditLogの認可ポリシー
- 403レスポンス
- UI表示とは独立したサーバー側認可

### 受入条件

- 要件の認可マトリクスをテーブル駆動テストで網羅する。
- Route Handler、ユースケース、UIで矛盾する認可定義を持たない。
- 担当外Deal更新を拒否できる。

### 検証

```bash
pnpm test:auth
```

## ISSUE-008: Customerドメイン・API・検索を実装する

- 種別: feature
- 依存: ISSUE-007
- 目的: 顧客のCRUDと検索条件を複数層に分離して提供する。

### スコープ

- Customerドメイン、repository、use case
- Route HandlersとZod schema
- 一覧、詳細、作成、更新、削除
- 名前、メール、電話番号、ステータス、担当者の検索・絞り込み

### 受入条件

- 電話番号等の任意項目を `null` として正規化する。
- ページングと既定並び順が固定されている。
- Customer削除は関連データを含むトランザクションとして実行する。
- APIエラー形式が共通仕様に従う。

### 検証

```bash
pnpm test:customer
```

## ISSUE-009: Customer画面を実装する

- 種別: feature
- 依存: ISSUE-008
- 目的: 顧客一覧、詳細、作成、編集、削除をUIから利用できるようにする。

### スコープ

- Customer一覧・詳細・フォーム
- 検索、ステータス、担当者フィルター
- ページング
- 認可に応じた操作表示
- バリデーションとAPIエラー表示

### 受入条件

- URLから検索・絞り込み状態を再現できる。
- 空文字の任意項目で500エラーにならない。
- キーボードで主要フォーム操作を完了できる。
- 認可されない操作はUI非表示かつAPIでも拒否される。

### 検証

```bash
pnpm test:customer
pnpm test:e2e
```
