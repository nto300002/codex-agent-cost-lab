# Issueバックログ

TraceCRMとCodexコスト比較実験を、原則として1 Issue = 1 PRで実装できる単位へ分割したバックログです。

## 運用ルール

- Issue IDは `ISSUE-001` 形式で固定する。
- Issue本文の受入条件を満たしてから完了とする。
- 依存Issueが完了するまで実装を開始しない。
- スコープ外の変更が必要になった場合は、既存Issueを拡張せず別Issueに分ける。
- 実験の正解パッチ、隠しテスト、期待関連ファイルはCodexへ渡すリポジトリから隔離する。
- 技術バージョンと実験条件は、パイロット開始後に変更しない。

## 共通の完了条件

各Issueは、個別の受入条件に加えて次を満たす。

- 型チェック、Lint、対象テストが成功する。
- 新規依存を追加した場合は、理由とバージョンを記録する。
- DB、日時、乱数、外部通信に起因する非決定性を増やさない。
- 秘密情報、正解パッチ、隠し評価情報を公開対象へ含めない。
- 仕様変更があれば、同じPRで関連文書を更新する。
