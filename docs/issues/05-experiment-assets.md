## ISSUE-018: 6件の実験タスク定義を作成する

> 実装済み: 6件の公開Briefとoperator定義を分離し、共通開始コミット、粒度、再現手順、禁止変更、人間時間、必須項目を静的検査できるようにした。

- 種別: experiment
- 依存: ISSUE-017
- 目的: G-A、G-B、G-Cに修正・実装タスクを1件ずつ用意する。

### スコープ

- GA-F1、GA-I1
- GB-F1、GB-I1
- GC-F1、GC-I1
- 再現手順、受入条件、禁止変更、人間の標準作業時間

### 受入条件

- タスク粒度を関連ファイル数、層数、受入条件数で説明できる。
- 各タスクが独立し、同じ開始コミットへ戻せる。
- Codexへ渡す情報とオペレーター専用情報が分離されている。

### 検証

- タスク定義テンプレートの必須項目を静的検査する。

## ISSUE-019: 開始状態と正解パッチを作成する

> 実装済み: 6タスクの開始状態と人間作成の参照パッチを非公開評価リポジトリへ分離し、コミットとSHA-256を公開側で固定した。全タスクで開始時失敗→参照適用後成功を自動確認する。

- 種別: experiment
- 依存: ISSUE-018
- 目的: 各タスクの再現可能な不具合・未実装状態と参照解を用意する。

### スコープ

- タスク別開始コミットまたは適用パッチ
- 人間が作成した正解パッチ
- 期待関連ファイルと変更量
- 標準作業時間の記録

### 受入条件

- 開始状態でタスク固有の評価が失敗する。
- 正解パッチ適用後は公開・隠し評価が成功する。
- 正解パッチをCodexの作業ツリーへ配置しない。

### 検証

- 各タスクで開始状態→失敗、正解適用→成功を自動確認する。

```bash
EXPERIMENT_ASSET_ROOT=/path/to/codex-agent-cost-lab-evaluation \
  pnpm experiment:verify-task-assets
```

## ISSUE-020: 隠し評価テストと採点ルールを作成する

> 実装済み: リポジトリ外の隠し評価、公開回帰、変更範囲、禁止変更を100点満点で採点し、成功判定・内訳・失敗理由をJSON保存する。6タスクすべてで正解100点、未変更と意図的誤答の不合格を確認する。

- 種別: experiment
- 依存: ISSUE-019
- 目的: Codexの自己申告に依存せず成功と品質を判定する。

### スコープ

- タスク別隠しテスト
- 回帰テスト、型チェック、禁止変更
- successとquality scoreの計算
- 部分点と失敗理由

### 受入条件

- 隠しテストをベースリポジトリ外から実行できる。
- 正解パッチは満点になる。
- 明らかな不完全実装、過剰変更、禁止変更を失敗として検出できる。
- 評価結果を機械可読な形式で保存する。

### 検証

- 正解、未変更、意図的誤答の3種類で評価器を検証する。

評価結果の公開契約は`experiment/evaluation-result.schema.json`、評価ロジックと隠しテストは公開リポジトリ外で管理する。
