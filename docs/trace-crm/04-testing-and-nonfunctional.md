# テストと非機能要件

## 15. テスト要件

### 15.1 単体テスト

対象:

- Zodスキーマ
- ドメインルール
- 認可ポリシー
- 日時処理
- CSV変換
- エラー変換

### 15.2 結合テスト

対象:

- Route Handler
- Application Service
- Prisma Repository
- トランザクション
- 認証・認可
- 絞り込み

### 15.3 E2Eテスト

最低限のシナリオ:

1. MEMBERがログインする
2. 担当顧客を閲覧・編集する
3. 担当外顧客へアクセスして拒否される
4. MANAGERが顧客一覧を絞り込む
5. MANAGERがCSVを出力する
6. ADMINがUserのロールを変更する
7. ADMINがAuditLogを閲覧する

### 15.4 ベースライン品質

実験用タスク適用前の基準コミットで、以下がすべて成功する。

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm build
```

### 15.5 テスト実行時間の目安

| コマンド | 目標 |
|---|---:|
| 単一機能テスト | 10秒以内 |
| 全単体・結合テスト | 60秒以内 |
| E2E | 120秒以内 |
| build | 120秒以内 |

実行環境によって変わるため、絶対条件ではなく設計目標とする。

## 16. 非機能要件

### 16.1 再現性

- 実験開始コミットを記録
- DB初期化を1コマンドで実行
- 外部通信なし
- Clockを固定可能
- テスト結果が実行順に依存しない

### 16.2 可観測性

アプリ自体には高度なAPMを実装しない。

Codex側の以下を観測対象とする。

- JSONLイベント
- コマンド実行
- トークン使用量
- Git差分
- テスト結果
- 実行時間

### 16.3 セキュリティ

- 実在する個人情報を使用しない
- `.env.example`のみコミット
- 秘密情報を必要としない
- DBはローカルファイル
- 本番デプロイを前提としない
- 依存パッケージ追加は実験タスクで明示されない限り禁止

### 16.4 性能

- Seedデータ規模で主要画面が通常操作可能
- 大規模性能試験は対象外
- N+1が極端に発生しない
- ページネーションは顧客・商談一覧へ実装する

### 16.5 コード規模

設計目標:

| 対象 | 目安 |
|---|---:|
| ソースファイル | 100〜180 |
| テストファイル | 30〜70 |
| 総ファイル | 160〜300 |
| 本体コード | 8,000〜18,000行 |
| テストコード | 3,000〜8,000行 |

規模を目的化せず、自然な機能分割を優先する。
