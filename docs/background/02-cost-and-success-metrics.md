# コストと成功指標

## 7. 消費トークンの計算方法

### 7.1 Codexから取得する値

Codexの各`turn.completed`イベントから、次の値を取得する。

| 記号    | JSONL項目                   | 意味                   |
| ----- | ------------------------- | -------------------- |
| (I_t) | `input_tokens`            | ターンtの入力トークン          |
| (C_t) | `cached_input_tokens`     | 入力のうちキャッシュから読まれたトークン |
| (O_t) | `output_tokens`           | ターンtの出力トークン          |
| (R_t) | `reasoning_output_tokens` | 出力のうち推論に使用されたトークン    |

OpenAIの使用量形式では、キャッシュ入力は入力トークンの内訳として記録される。推論トークンも出力トークンの内訳であり、出力トークンとして課金されるため、総量や料金の計算で二重加算しない。

### 7.2 1実行に複数ターンがある場合

Codexが1回の実験中に複数のターンを実行した場合、すべての`turn.completed`を合計する。

[
I_{\mathrm{run}}=\sum_{t=1}^{n}I_t
]

[
C_{\mathrm{run}}=\sum_{t=1}^{n}C_t
]

[
O_{\mathrm{run}}=\sum_{t=1}^{n}O_t
]

[
R_{\mathrm{run}}=\sum_{t=1}^{n}R_t
]

ここで、(n)はその実行に含まれる完了ターン数である。

サブエージェントを使用する条件では、対象実行に属するサブエージェント分も含めて集計する。

### 7.3 非キャッシュ入力トークン

`input_tokens`にキャッシュ入力が含まれる形式では、非キャッシュ入力を次のように計算する。

[
N_{\mathrm{run}}
================

I_{\mathrm{run}}-C_{\mathrm{run}}
]

* (N_{\mathrm{run}})：非キャッシュ入力
* (I_{\mathrm{run}})：入力トークン全体
* (C_{\mathrm{run}})：キャッシュ入力

データ不整合への安全策として、実装では次のようにする。

[
N_{\mathrm{run}}
================

\max(I_{\mathrm{run}}-C_{\mathrm{run}},0)
]

### 7.4 総消費トークン

実行全体でモデルが処理した論理上の総トークンは、次のように定義する。

[
T_{\mathrm{run}}
================

I_{\mathrm{run}}+O_{\mathrm{run}}
]

または、課金区分を明示する場合は、

[
T_{\mathrm{run}}
================

N_{\mathrm{run}}
+
C_{\mathrm{run}}
+
O_{\mathrm{run}}
]

となる。

(N_{\mathrm{run}}+C_{\mathrm{run}}=I_{\mathrm{run}})であるため、両式の結果は同じである。

### 7.5 推論トークンの扱い

推論トークンは次の計算へ別途足さない。

誤った例：

[
I+O+R
]

正しい例：

[
I+O
]

(R)は(O)の内訳として、次の分析に使用する。

* プロンプト条件によって推論量が増減したか
* 追加の探索が推論量にも影響したか
* G-A、G-B、G-Cで推論比率が変わるか

推論トークン比率は次のように計算する。

[
推論比率
====

\frac{R_{\mathrm{run}}}{O_{\mathrm{run}}}
\times100
]

### 7.6 トークン削減量

同一タスク・同一粒度におけるP0と比較条件Pxの中央値を用いる。

$$
\text{トークン削減量} =
\operatorname{median}(T_{P0}) -
\operatorname{median}(T_{Px})
$$

### 7.7 トークン削減率

$$
\text{トークン削減率} =
\frac{
\operatorname{median}(T_{P0}) -
\operatorname{median}(T_{Px})
}{
\operatorname{median}(T_{P0})
}
\times100
$$

例：

* P0の総トークン中央値：200,000
* P1の総トークン中央値：160,000

[
\frac{200,000-160,000}{200,000}\times100
=20%
]

この場合、P1はP0より総トークン中央値が20%少ない。

### 7.8 入力・出力を分けて表示する

総トークンだけでは、どこが改善されたか分からない。

次を別々に示す。

[
入力削減率
=====

\frac{
\operatorname{median}(I_{P0})
-----------------------------

\operatorname{median}(I_{Px})
}{
\operatorname{median}(I_{P0})
}
\times100
]

[
出力削減率
=====

\frac{
\operatorname{median}(O_{P0})
-----------------------------

\operatorname{median}(O_{Px})
}{
\operatorname{median}(O_{P0})
}
\times100
]

[
キャッシュ率
======

\frac{C_{\mathrm{run}}}{I_{\mathrm{run}}}
\times100
]

入力削減率が低くても、キャッシュ率が高ければ、実際のクレジット消費が下がる可能性がある。

## 8. 消費クレジット・料金の計算方法

Codexの現行レート表は、100万トークン当たりの入力、キャッシュ入力、出力の各レートでクレジットを計算する。実際のレートはモデルによって異なるため、実験時点の公式レートを記録する。

### 8.1 記号

* (r_i)：100万非キャッシュ入力トークン当たりのクレジット
* (r_c)：100万キャッシュ入力トークン当たりのクレジット
* (r_o)：100万出力トークン当たりのクレジット

### 8.2 1実行の消費クレジット

[
Credit_{\mathrm{run}}
=====================

\frac{N_{\mathrm{run}}}{1,000,000}r_i
+
\frac{C_{\mathrm{run}}}{1,000,000}r_c
+
\frac{O_{\mathrm{run}}}{1,000,000}r_o
]

推論トークンは出力トークンに含まれるため、別項目として加算しない。

### 8.3 計算例

仮に次の実行結果だったとする。

* 入力トークン：100,000
* キャッシュ入力：70,000
* 出力トークン：5,000

非キャッシュ入力は、

[
100,000-70,000=30,000
]

となる。

使用モデルのレートを仮に次とする。

* 入力：43.75クレジット／100万トークン
* キャッシュ入力：4.375クレジット／100万トークン
* 出力：350クレジット／100万トークン

[
Credit_{\mathrm{run}}
=====================

\frac{30,000}{1,000,000}\times43.75
+
\frac{70,000}{1,000,000}\times4.375
+
\frac{5,000}{1,000,000}\times350
]

[
=1.3125+0.30625+1.75
]

[
=3.36875クレジット
]

このレートは例であり、実際には実験時点で使用するモデルの公式レートへ置き換える。

### 8.4 円換算

1クレジット当たりの実質的な円価格を確認できる場合は、次のように換算する。

[
Cost_{\mathrm{JPY}}
===================

Credit_{\mathrm{run}}
\times
1クレジット当たり円価格
]

ただし、ChatGPTプランに含まれる利用枠、追加購入クレジット、法人契約では、1クレジット当たりの実質価格が異なる可能性がある。

そのため、LTでは次を分けて表示する。

* 消費トークン
* 消費クレジット
* API単価相当額
* 実際の請求額

円価格を確定できない場合は、無理に円へ変換せず、クレジット数を主要指標とする。

### 8.5 API単価相当額

APIとして使用する場合は、次の式を使う。

[
Cost_{\mathrm{USD}}
===================

\frac{N_{\mathrm{run}}}{1,000,000}p_i
+
\frac{C_{\mathrm{run}}}{1,000,000}p_c
+
\frac{O_{\mathrm{run}}}{1,000,000}p_o
]

* (p_i)：100万入力トークン当たりのドル価格
* (p_c)：100万キャッシュ入力トークン当たりのドル価格
* (p_o)：100万出力トークン当たりのドル価格

OpenAI APIでも、入力・キャッシュ入力・出力は異なる単価で扱われる。

## 9. 成功率と成功1件当たりコスト

### 9.1 成功率

Codexの自己申告ではなく、隠しテスト、回帰テスト、型チェック、禁止変更検査で成功を判定する。

[
成功率
===

\frac{成功した実行数}{全実行数}
\times100
]

例：

* 全実行：10回
* 成功：8回

[
\frac{8}{10}\times100=80%
]

### 9.2 成功1件当たり消費クレジット

条件ごとの全実行コストを、成功した実行数で割る。

[
成功1件当たりクレジット
============

\frac{
\sum Credit_{\mathrm{run}}
}{
成功した実行数
}
]

失敗した実行も分子へ含める。

失敗実行にもクレジットが消費されるため、失敗を除外すると実際の運用コストを過小評価する。

### 9.3 成功1件当たりAI料金

[
成功1件当たりAI料金
===========

\frac{
全実行のAI料金合計
}{
成功した実行数
}
]

### 9.4 成功1件当たり総原価

人間のレビューと修正を含める場合は、次の式を使用する。

[
成功1件当たり総原価
==========

\frac{
AI料金
+
レビュー費
+
追加修正費
}{
成功した実行数
}
]

人間の費用は、次のように計算する。

[
人件費
===

作業時間
\times
1時間当たり会社負担単価
]

例：

* 追加修正：10分
* 会社負担単価：5,000円／時間

[
10分=\frac{10}{60}時間
]

[
\frac{10}{60}\times5,000
\approx833円
]

AI料金が50円安くても、人間の修正費が833円増えれば、総原価は悪化する。
