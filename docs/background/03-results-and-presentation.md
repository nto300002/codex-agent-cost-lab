# 想定結果と発表設計

## 10. 想定する結果

以下は実験前の仮説であり、実測結果ではない。

### 想定1：G-Aでは大きな差が出ない

局所タスクでは、P0でも正しいファイルを早期に発見できる可能性が高い。

そのため、次の結果が考えられる。

* P0・P1・P2で成功率がほぼ同じ
* 構造化プロンプトの入力増加分だけP1が高くなる
* `AGENTS.md`の読み込み分だけP2が高くなる
* 探索ファイル数にはほとんど差がない

この結果になった場合、

> すべての小さなタスクへ長いテンプレートを適用する必要はない

という結論になる。

### 想定2：G-Bで最も分かりやすい差が出る

G-Bでは複数の層を調べる必要がある一方、対象範囲を適切に限定できる。

そのため、P1・P2では次の改善が期待される。

* 対象外ファイルの参照減少
* 横断検索の減少
* テスト対象の限定
* 不要な修正の減少
* 再試行の減少
* 成功率を維持したままクレジットを削減

LTで最も説明しやすい結果は、このG-Bで現れる可能性が高い。

### 想定3：G-Cではトークン差と成功率差が大きくなる

横断タスクでは、調査対象と制約が多くなる。

P0では次の問題が起きる可能性がある。

* 広い範囲を繰り返し検索する
* 同じファイルを再参照する
* 全テストを何度も実行する
* 無関係なリファクタリングを始める
* 完了条件が不明で作業を続ける

一方、P1・P2で探索範囲を狭くしすぎた場合、必要な関連ファイルを見落とし、成功率が下がる可能性もある。

したがってG-Cでは、

> トークンを最も減らした条件が、最も良い条件とは限らない

という結果を想定する。

### 想定4：P2が常に最安とは限らない

`AGENTS.md`自体も入力コンテキストになる。

そのため、次のような結果があり得る。

* G-AではP0が最安
* G-BではP1が最安
* G-CではP2の成功率が最も高い
* P2は総入力が増えても、再試行が減って最終コストが下がる
* 過剰な`AGENTS.md`では、指示に従うため探索やテストが増える

別の研究では、不要なリポジトリ指示が探索とテストを広げ、推論コストを20%以上増やし、成功率を下げる傾向も報告されている。

最初から「AGENTS.mdは有効」という結論を設定せず、タスク粒度ごとの使い分けを検証する。

## 11. 発表として成立する結果

発表は、P1・P2がP0より安くなった場合だけ成立するわけではない。

### 結果A：構造化によって安くなった

着地：

> 曖昧な依頼による1回数十円の寄り道が、組織全体では年間数百万円になる可能性がある。

### 結果B：小規模タスクでは差がなかった

着地：

> プロンプトの構造化は一律に行うのではなく、探索範囲が広いタスクへ適用すべきである。

### 結果C：トークンは減ったが成功率も下がった

着地：

> トークン削減をKPIにすると、失敗と人間の手戻りを増やす可能性がある。

### 結果D：AGENTS.mdを入れた方が高くなった

着地：

> リポジトリ指示書は節約装置ではなく、内容と適用範囲を管理すべきコスト要因である。

### 結果E：実行ごとのばらつきが大きかった

着地：

> 1回のデモ結果から費用を判断してはいけない。AIエージェントの予算管理には反復測定が必要である。

### 3. 成功1件当たりコスト

単純な総トークンではなく、次を中心指標とする。

[
成功1件当たりクレジット
============

\frac{
全実行の消費クレジット合計
}{
成功した実行数
}
]

### 4. 会社規模への換算

実測した1タスク当たりの差を、次のような仮定へ当てはめる。

* AI利用者：60人
* 1人1日：6タスク
* 月間営業日：20日

月間タスク数は、

[
60人\times6件\times20日
=7,200件
]

1タスク当たりの料金差を(\Delta c)円とすると、

[
月間差額
====

7,200\times\Delta c
]

[
年間差額
====

7,200\times\Delta c\times12
]

例えば、1タスク当たり50円の差なら、

[
7,200\times50
=360,000円／月
]

[
360,000\times12
=4,320,000円／年
]

つまり月36万円、年432万円となる。

ただし、すべての業務タスクが実験タスクと同じ費用差になるとは限らないため、これは「会社全体へそのまま適用できる予測」ではなく、規模感を示すシナリオとして扱う。

### 5. 削減額の3シナリオ

| シナリオ | 1タスク当たり差 |  月間差額 |   年間差額 |
| ---- | -------: | ----: | -----: |
| 保守   |      10円 | 7.2万円 | 86.4万円 |
| 標準   |      50円 |  36万円 |  432万円 |
| 強気   |     100円 |  72万円 |  864万円 |

実際の発表では、実験で得た中央値または成功1件当たりの差を代入する。

## 13. 本実験で示せないこと

本実験だけでは、次を証明できない。

* すべての企業で同じ削減率になる
* すべてのリポジトリでP2が有効である
* プロンプトだけで会社全体のAI費用を管理できる
* Codex以外のエージェントでも同じ結果になる
* 1種類のMini CRMが受託開発全体を代表する
* 短縮された時間がそのまま利益へ変わる
* クレジット換算額と実際の会社請求額が常に一致する

本実験で示すのは、次の範囲である。

> 制御された一つのコードベースにおいて、仕事の与え方がCodexの探索行動・トークン消費・成功率へどのような差を生むか。

## 14. 発表の最終的な着地点

この実験の目的は、「長いプロンプトを書こう」「AGENTS.mdを必ず導入しよう」という結論を出すことではない。

最終的には、次の主張へつなげる。

> AIエージェントの無駄遣いは、モデル単価だけでなく、仕事の境界と終了条件が定義されていないことから生じる。

> ただし、情報を削りすぎれば成功率が下がる。管理すべきなのは総トークン数ではなく、成功した仕事1件当たりのコストである。

> 個人が適切なプロンプトを書くことは第一歩にすぎない。組織では、計測、共通指示、モデル選択、停止条件、成功判定を開発基盤として管理する必要がある。

* Gloaguen et al., *Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?*, 2026。不要な指示による探索・テスト・推論費用の増加を報告。
