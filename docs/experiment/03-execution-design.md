# 実行設計

## 9. 実験デザイン

### 9.1 完全交差で実行する

各タスクを、すべてのプロンプト条件で実行する。

例:

```text
GA-F1 × P0
GA-F1 × P1
GA-F1 × P2

GB-F1 × P0
GB-F1 × P1
GB-F1 × P2
```

P0を小規模タスク、P2を大規模タスクだけに適用してはいけない。

### 9.2 繰り返し回数

AIエージェントは同じタスクでも探索経路とトークン消費が変動するため、1条件1回では判断しない。

#### パイロット

- 各粒度1タスク
- 3プロンプト条件
- 各5回
- 合計45実行

#### LT向け標準

- 各粒度2タスク
- 3プロンプト条件
- 各5回
- 合計90実行

#### より安定した比較

- 各粒度3タスク
- 3プロンプト条件
- 各5回
- 合計135実行

予算が限られる場合も、タスク数を増やして繰り返し回数を1回にするより、最低3回、推奨5回の反復を優先する。

### 9.3 実行順序

実行順をランダム化または交互配置する。

悪い例:

```text
P0をすべて実行
P1をすべて実行
P2をすべて実行
```

推奨例:

```text
GA-F1-P1-run1
GB-I1-P0-run1
GC-F1-P2-run1
GA-I1-P2-run1
...
```

これにより、時間帯、モデル更新、サービス側負荷、キャッシュの影響が一条件へ偏ることを減らす。

## 10. 固定する条件

以下は全実行で同一にする。

- Codex CLIバージョン
- モデル名
- reasoning effort
- sandbox設定
- approval policy
- ネットワークアクセス
- MCP設定
- Git開始コミット
- OS
- CPU・メモリ
- Node.js等のランタイム
- 依存パッケージ
- タイムアウト
- 最大実行時間
- 評価スクリプト
- 隠しテスト
- 料金・クレジットレートの基準日

### 10.1 Codex設定の混入防止

実験専用の `CODEX_HOME` を用意する。

専用環境には認証情報と実験に必要な最小設定だけを置き、次を含めない。

- 個人用 `AGENTS.md`
- 個人用 `AGENTS.override.md`
- 個人のMCP設定
- タスク固有のRules
- 記憶・過去セッション
- 実験に不要なSkill

Codexは実行開始時にグローバルおよびプロジェクトの `AGENTS.md` を読み込むため、P0・P1へ意図せず個人用指示が入らないようにする。

## 11. 1実行の手順

1. 実験用リポジトリを開始コミットへ戻す
2. 未追跡ファイルを削除する
3. 依存関係とテストキャッシュを所定の状態へ戻す
4. 条件に応じて `AGENTS.md` を設置または除去する
5. 新規Codexセッションで実行する
6. `codex exec --json` の標準出力をJSONLへ保存する
7. Git差分を保存する
8. Codexから隔離した隠しテストを実行する
9. 型チェック・静的解析・禁止変更検査を実行する
10. 評価結果をJSONへ保存する
11. JSONL、評価結果、差分を集計CSVへ変換する

### 11.1 実行コマンド例

```bash
codex exec \
  --json \
  --sandbox workspace-write \
  --ignore-user-config \
  --ignore-rules \
  -C "$WORK_DIR" \
  "$(cat "$PROMPT_FILE")" \
  > "$RESULT_DIR/codex.jsonl"
```

実際の利用環境に応じてモデル名とreasoning effortを明示する。
