# Experiment prompts

6タスクに対するP0・P1・P2の18プロンプトを管理する。すべての条件は対象タスクの公開Briefを唯一のタスク事実源として生成する。

## 条件差のレビュー表

| 条件 | タスク事実                                                                   | 指示構造                                                             | リポジトリ共通指示                     |
| ---- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------- | -------------------------------------- |
| P0   | 公開BriefのRequest・Acceptance criteria・Constraints・Validationをすべて含む | 現場で自然な短い依頼。専用の節構造なし                               | なし                                   |
| P1   | P0と同一                                                                     | 目的、仕様、調査、変更範囲、禁止範囲、テスト、停止、完了、報告を明示 | なし                                   |
| P2   | P1と同一                                                                     | P1とバイト単位で同一                                                 | 最小`AGENTS.md`を別途配置（ISSUE-022） |

P1とP2のタスクプロンプトは同一であり、差はP2実行時に配置する`AGENTS.md`だけとする。P0にも全タスク事実を含め、P1/P2だけに実装箇所、原因、参照パッチ、隠し評価を追加しない。

## 生成と検査

```bash
pnpm experiment:render-prompts
pnpm experiment:validate-prompts
```

- `templates/`: P0とP1/P2の決定論的テンプレート
- `P0/`、`P1/`、`P2/`: 実験ランナーが使用する生成済みプロンプト
- `manifest.json`: 公開Brief由来の事実ハッシュと各プロンプトのSHA-256

静的検査では18件の完全性、P1/P2一致、全公開事実の包含、必須節、未置換変数、オペレーター専用情報の混入、P0の過度な情報欠落を確認する。人手レビューでは上表と各粒度の代表3件（GA-F1、GB-I1、GC-F1）を確認する。
